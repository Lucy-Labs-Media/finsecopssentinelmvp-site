The problem

Three leaks, one blind spot

Most teams treat these as separate problems. They are the same problem: spend you cannot attribute, in time to act on it.

1

Unattributed keys

An API key has been billing for eight months. Nobody can tell you whose it is, or whether the pipeline behind it still exists.

2

Runaway agents

A retry loop runs from Friday night to Monday morning. It surfaces as a line item three weeks later, already paid.

3

Margin-negative customers

If you sell an AI product, some customers cost more to serve than they pay you. Your P&L will not say which until the quarter closes.

Why it finds what others miss

Cost per token is an engineering metric

Cost per resolved outcome is a business one: API spend, plus vector and guardrail infrastructure, plus the human rework required when the model gets it wrong — divided by the outcomes actually closed.

The Efficiency Trap

A support workflow moves to a model four times cheaper. Direct AI cost per ticket falls, and every token dashboard reports a win. But the rework rate climbs from 15% to 55% — and once you count the human time spent fixing the output, the true cost per resolved ticket more than doubles.

4×cheaper per token
2.1×more expensive per outcome

Rework time comes from your ticketing export — Zendesk, Jira, or a simple CSV. Where you do not track it, a configured estimate is used and labelled as an estimate, never passed off as measured.

Why it is safe to point at real data

Nothing leaves your machine

No egress, by architecture

Billing data is parsed into browser memory and never written to disk, stored in a database, or transmitted anywhere. Enforced by automated sweeps that fail the build — and by a Content-Security-Policy that forbids outbound requests at the browser level.

No enforcement path

Sentinel cannot revoke a key, change infrastructure, or stop a job. Every recommendation is a simulation you approve. Your application cannot go down because of us.

Nothing to integrate

No SDK, no agent, no code in your critical path. It reads exports you already have — so your security review is a conversation, not a quarter.

Questions

Common questions

Where does our billing data go?
Into browser memory, for the length of the session. No disk, no database, no network. Enforced by automated sweeps that fail the build if anyone adds a storage or network call to a data path, and by a Content-Security-Policy that forbids outbound requests. When you close the tab, it is gone.
How do we know the math is right?
A signed specification defines every formula, rounding rule and error state. The worked examples in that specification are the acceptance tests, and independent verifier agents audit the implementation against it on every build. All money is exact decimal arithmetic — no floating point anywhere in a calculation path. One command re-runs all of it on your machine.
What if a finding is wrong and we act on it?
Everything is a simulation you approve. Sentinel has no path into your systems — it cannot revoke keys, change infrastructure, or stop a job. The pilot includes a joint review session where you mark each finding verified, disputed, or already known. Only verified findings are in scope for any fee.
Our exports are messy. Will that break it?
That is the interesting case. Unmappable rows are quarantined with their row number and a reason code and surfaced as findings, never dropped. A data readiness score tells you what fraction of your data actually made it through. Messy data does not break it; it gets measured.
Which providers are supported?
Eight billing sources — AWS Cost and Usage Reports, Azure Cost Management, GCP Billing, OpenAI, Anthropic, Gemini, Databricks and Snowflake — plus three outcome sources for rework data: Zendesk, Jira and a generic CSV. Adding another is a configuration entry, not an engineering project.
How is this different from Vantage, Langfuse or a gateway?
Gateway tools sit in your call path — better data, real enforcement, an integration project and a security review. SDK tracing tools instrument your code, with rich per-call detail but still measuring machine cost only. Billing platforms read your invoices with no integration, but no outcome dimension. Sentinel is the third category with the thing none of them have: the human cost of bad output, and a local-first architecture that makes it installable this week. If you can deploy an SDK and want live guardrails, those tools are better at that.
Can we see the source code?
Under a mutual NDA, yes — including the calculation specification, architecture documentation and the full engineering history. The repository is private; access is granted for evaluation.
